# IQC 平台开发任务拆分

## 1. 执行规则

1. 先完成设计决策和接口契约，再实现页面或业务代码。
2. 每个阶段必须通过验收标准后才能进入下一阶段。
3. 任务按“可独立验收的垂直切片”拆分，避免只做没有真实闭环的页面。
4. 前端、后端、数据库和权限资源必须在同一任务上下文中定义，避免接口和权限后补。
5. 所有涉及客户沟通内容的功能，必须同时定义数据范围、脱敏和审计行为。

## 2. 阶段总览

```text
P0 设计冻结与工程基线
 ↓
P1 独立登录/权限/布局
 ↓
P2 会话上传与 txt 解析
 ↓
P3 Agent、规则和评分配置
 ↓
P4 手动质检任务与异步执行
 ↓
P5 结果中心与可解释详情
 ↓
P6 总览、导出、审计和质量门禁
```

二期能力（版本运营、样本库、复核、申诉、定时/抽样任务）必须在一期验收后另立计划，不与 MVP 混做。

## 3. P0：设计冻结与工程基线

### 任务

- 确认 OAuth2 client、回调、token/session 策略。
- 确认 IQC 服务名、网关前缀、数据库 schema、文件存储方案。
- 将 `iqc-platform-admin` 的 UI 基线切换为 Ant Design Vue。
- 建立 API 错误码、分页、时间、文件上传和异步任务状态约定。
- 建立 `iqc` 应用的菜单和资源权限命名规则。
- 建立独立前端 CI：type-check、build、单元测试和产物检查。
- 建立 IQC 后端 Maven 工程，使用 OpenSabre Framework BOM 和 Starter；核对治理、持久化、缓存、注册和 Web 能力的真实 API。
- 明确 IQC 应用名、错误码/字典注册快照、治理 Token 和基础配置。

### 验收

- 独立前端可在无 `opensabre-admin` 源码引用的情况下构建。
- Ant Design Vue 依赖和主题配置完成，Element Plus 不再出现在 IQC 依赖中。
- 后端能基于 Framework 启动最小服务，并通过真实接口验证审计、限次、计次、字典和错误码接入。
- 关键未决决策在 `docs/architecture.md` 中全部关闭或明确记录责任人。

## 4. P1：独立登录、权限与工作台

### 任务

- 实现 OAuth2 登录回调和登录失效处理。
- 实现当前用户、组织/部门上下文和权限加载。
- 实现 IQC 独立 Layout、Ant Design Menu、面包屑和用户菜单。
- 接入 `iqc:*` 菜单/资源权限；无权限页面返回 403。
- 完成总览、会话、任务、结果、Agent、规则、模板的空状态页面。

### 验收

- 未登录访问业务路由会进入登录流程。
- 用户没有某个资源权限时，前端不显示操作入口，后端接口仍拒绝越权请求。
- 刷新页面后用户和权限状态可恢复。
- 1024px 宽度下主要布局不出现横向溢出。

## 5. P2：会话上传与 txt 解析

### 任务

- 后端建立 Conversation、ConversationMessage 和导入记录。
- 文件上传入口接入 Framework/治理限次，成功和失败导入通过 Usage Counter 记录。
- 实现 txt 文件类型/大小/编码校验。
- 实现格式：`<序号>(<角色>):[<HH:mm:ss>] <正文>`。
- 返回解析成功数、失败数、错误行和可定位原因。
- 前端实现上传、导入结果、会话列表和会话详情。
- 加入原始文件与解析消息的追溯关系。

### 验收

- 用户提供的 5 行样例可完整解析为 5 条消息。
- 角色、时间、序号或正文非法时，错误行不会静默丢失。
- 同一文件重复提交不会产生不可识别的重复会话，重复策略有明确提示。
- 会话列表和详情遵守本人/部门/全部数据范围。

## 6. P3：Agent、规则和评分配置

### 任务

- 建立 Agent、AgentVersion、Rule、ScorePolicy 数据模型。
- 实现规则类型：关键词、正则、结构化条件；预留 LLM 判断规则。
- 实现 Agent 草稿、测试、发布、停用的最小状态机。
- Agent/规则写操作接入统一审计，字典字段通过 Framework 字典能力声明或读取。
- 实现规则启停、分类、目标角色、扣分、风险等级和一票否决。
- 前端实现列表、编辑表单、规则测试和发布确认。
- 生成可用于任务执行的不可变配置快照。

### 验收

- 未发布 Agent 不能创建质检任务。
- 已执行任务关联的 Agent/规则配置修改后，历史结果依据不变。
- 关键词和正则规则测试结果可复现，并返回命中片段。
- Agent 发布/停用和规则修改都能查询到审计记录。

当前实现进度：已完成 Agent/规则创建、追加版本、提交审批、审批通过、驳回与查询，且前端创建新版本后自动提交审批；已完成关键词、正则和结构化条件确定性执行，规则测试接口和前端测试入口，规则分类、目标说话人、命中扣分/风险等级/一票否决配置，任务多规则选择和不可变规则数组快照，以及 Agent/规则追加式版本历史。结构化条件使用白名单 JSON 字段/操作符及 `all/any/not` 组合，不执行脚本。

## 7. P4：手动任务与异步质检执行

### 任务

- 实现 Task、TaskItem、TaskExecution 状态模型。
- 实现手动选择会话、Agent 快照和执行任务。
- 实现规则预检、LLM 适配器、结构化结果校验和结果落库。
- 实现任务进度、单会话失败、失败重试、取消和幂等。
- 任务创建/执行和 LLM 调用接入治理限次；任务、会话处理、规则命中和模型调用使用稳定 recordId 计次。
- 所有异常映射到 OpenSabre 错误码目录，前端按统一错误结构展示。
- 前端实现任务创建、任务列表、详情进度和错误明细。
- 增加任务执行审计和敏感模型调用日志（不记录密钥和完整原文）。

### 验收

- 任务状态至少支持 `CREATED、QUEUED、RUNNING、SUCCEEDED、PARTIAL_FAILED、FAILED、CANCELLED`。
- 刷新任务详情后进度和结果数量保持一致。
- 重复点击执行不会启动两个有效执行实例。
- 单个会话失败不影响其他会话完成；重试不会覆盖已成功结果。
- LLM 返回非法结构时任务项进入可诊断失败状态。

当前实现进度：已完成手动任务创建、查询、详情、取消（含 RUNNING）、异步入队、执行实例、TaskItem 分片、单条失败隔离、进度记录、详情轮询、失败状态、只重试失败消息的 attempt 重试，以及消息级 Usage Counter 的稳定事件计次；同一消息的 `ATTEMPT` 与 `SUCCESS/FAILURE` 使用不同且稳定的事件 `recordId`。OpenSabre 当前接收端会传播该标识，但分钟聚合尚未证明按 `recordId` 去重，跨重试幂等仍需治理端补强/运行验证。LLM 已提供默认关闭的 OpenAI-compatible HTTP 适配器：结构化 JSON 校验、超时、最多 3 次重试、调用前脱敏，并复用 OpenSabre 同步限次与 Usage Counter；真实模型端点和治理运行时仍待环境验证。

## 8. P5：结果中心与可解释详情

### 任务

- 建立 InspectionResult、Finding、Evidence、Suggestion 等结果结构。
- 实现结果列表筛选：Agent、任务、人员、部门、风险、分数、状态。
- 实现会话原文与证据片段定位/高亮。
- 实现扣分明细、AI 理由、改进建议和执行快照摘要。
- 实现“我的质检”和团队结果的服务端数据范围控制。
- 敏感详情查看接入统一审计，结果接口使用 Framework 错误码和标准响应约定。

### 验收

- 每条结果都能展示分数、风险等级、命中规则、证据、扣分原因和建议。
- 证据片段可以回到会话消息序号或原文位置。
- 员工不能通过修改查询参数查看其他部门或其他员工的结果。
- 结果详情中的 Agent/规则/模型快照与任务执行时一致。

当前实现进度：已完成结果列表、命中状态、分数、风险、原因、Finding/Evidence/Suggestion 分层、消息位置、证据片段原文高亮、执行实例关联、结果详情、任务快照、按任务/Agent/人员/部门/状态/角色/风险/分数筛选、逐规则扣分明细和按筛选条件 CSV 导出；人员/部门筛选复用任务的 `createdBy`/`ownerGroupId` 与既有数据范围模型，未复制组织主数据。

## 9. P6：总览、导出、审计和质量门禁

### 任务

- 实现一期总览：会话数、平均分、不合格率、高风险数、趋势和任务状态。
- 实现模板中心、系统设置和操作日志入口：模板读取 IQC 内置模板接口；系统设置只展示模型安全状态；操作日志复用 `base-sysadmin` 审计查询，不在 IQC 建立审计存储。
- 菜单和页面操作入口按资源权限失败关闭，后端资源权限仍是最终校验。
- 会话、任务、结果列表统一采用分页查询，前端支持页码与每页条数控制。
- 实现结果导出，限制字段和数据范围。
- 接入平台审计日志，覆盖配置、任务、敏感查看和导出。
- 补充脱敏展示和 LLM 入参脱敏策略。
- 建立单元、接口集成、前端路由和关键流程 E2E 测试。
- 建立性能基线和错误监控字段。
- 验证审计事件、限次拒绝、计次幂等、字典启停项和错误码注册/查询。

### 验收

- 总览指标与结果查询口径一致，并可按时间/组织范围过滤。
- 导出权限、数据范围和审计记录同时生效。
- 核心流程测试覆盖“登录—上传—配置—执行—结果查看”。
- CI 在构建、类型检查、测试失败时阻止合并。

当前实现进度：已完成总览会话/任务/结果/平均分/命中数/高风险数/不合格率、按日结果/命中/高风险/不合格趋势、时间范围筛选、真实任务动态、Agent/质检人员 Top 5 排行、结果详情、CSV 导出、前端权限入口，以及基于 OpenSabre 组织服务的本人/同组/管理员数据范围；已补充只读运行时 smoke 脚本，真实认证、数据库、Nacos、网关和治理链路 E2E 仍待环境执行。E2E 依赖 IQC schema、Nacos 服务注册、网关应用路由和 `iqc-platform-local` OAuth2 client；相关配置文件和授权库迁移已准备。

## 10. 二期候选任务

按优先级排序：

1. Agent/规则完整版本管理和效果对比。
2. 定时、抽样和事件触发任务。
3. 样本库、误判/漏判标注和 Agent 评估。
4. 人工复核和申诉。
5. 质检报表和团队运营分析。
6. 多渠道接入、语音转写和图片/附件识别。

每个二期任务都必须重新补充领域模型、权限、审计、数据迁移和验收标准。

## 11. 风险与停止条件

| 风险 | 缓解措施 | 停止条件 |
| --- | --- | --- |
| OAuth2/权限接入不明确 | P0 先完成真实登录和权限探测 | 未确认 token/回调前不开发业务页面联调 |
| LLM 输出不稳定 | 结构化 schema、超时、重试和失败状态 | 没有可校验输出契约前不接入正式任务 |
| 原文隐私泄露 | 定义脱敏、审计和导出策略 | 未确认敏感数据边界前不接生产数据 |
| 配置修改影响历史结果 | 执行时保存版本快照 | 无快照方案前不允许发布任务 |
| 页面先行导致接口返工 | API contract-first，先写 DTO 和错误码 | 接口未评审前不写复杂页面 |
| Framework 能力接入偏差 | 先以 Starter 源码和测试核对真实 API，禁止复制实现 | 审计/限次/计次/字典/错误码任一能力未验证前不进入对应业务阶段 |

## 12. 推荐开发顺序

先做 P0 和 P1 的技术闭环，再以 P2→P5 的业务垂直切片推进，P6 作为一期发布门禁。每一阶段结束后进行一次设计/接口/安全复盘；如果复盘发现领域边界变化，先更新 SDD 和任务拆分，再继续编码。
