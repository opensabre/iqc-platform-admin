# 知识库管理

/knowledge-bases复用原路由/组织菜单与usePermission，新增领域文档表单而非第二套CRUD框架。目录分页只元数据，逐个详情/精确版本独立读取正文。正文受限视图不建空编辑器；草稿未保存时禁止跨资产和发布/恢复，命令后清正文再独立重读，已提交但重读失败保留ID并阻止重复提交。历史恢复只写新草稿，原版本及指针不变。

每份参考文档编辑稳定ID、标题、正文、来源引用，1–100份/单正文16000字/总200000字符；服务端再次严格验证。元数据回执和受限正文通过iqc-knowledge-read-v1/privacy.canonicalPayloadVisible区分。页面状态只保存解析文档，不重复保存原始草稿JSON；权限变化（包含敏感正文/目录/版本/维护）、卸载/关闭/切换的请求代次失效，旧回执或旧版本正文不得恢复。保持命令忙状态直到原HTTP结束，不因撤权重开另一写请求。

新增菜单和九项资源见组织迁移V20261024_01，脚本未执行。仅本批管理与阅读能力；Agent精确引用/原任务组交集冻结与LLM上下文仍后续。构建结果及真实权限、HTTP/SQL/浏览器验证范围以协作记录为准。

Agent 能力配置复用 PublishedAssetReference 选择知识库的精确发布版本，最多四个且不得重复；只有目录、历史、精确版本读取资源齐备才挂载选择器。选择器仅请求目录及版本元数据，选择变更清除旧摘要，服务端重新绑定。撤权使编辑状态与迟到响应失效；无知识库引用的旧配置不新增读取请求。共享配置仅存版本标识和摘要。

单租户沿用现有组织数据权限。任务正文冻结与模型上下文接入尚待 KB3；当前真实模型会明确拒绝未冻结的知识库上下文，不应将本批视为知识库推理上线。生产构建（含类型检查）退出0，保留已有大包告警；无部署。
