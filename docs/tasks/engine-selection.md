# 任务类型步骤：独立引擎配置

`TaskEngineSelector` 对应原型第二步“任务类型”，复用现有 Ant Design Vue 表单和规则、大模型配置数据。父级传入已有 API 加载的规则、模型及识别目标，不新增配置查询 API。

- 质检、打标可单选或同时选择，分别添加 REGEX / DLS / LLM；小模型只提示后续支持。
- 同类型允许多个实例；各操作按数组位置独立排序，上移/下移不改变另一操作。切换操作保留本组件生命周期内的草稿。
- 只显示对应类型的已发布规则、已发布且非 RULE_ONLY 的大模型配置。选择规则可查看表达式；请求仅提交引用 ID，不提交表达式或模型快照。
- 目标选项由结果处理配置和既有规则/标签数据提供；组件不创建新标签，不以命中直接写标签。
- `validate()` 在向导下一步或提交前校验：至少选择一项，每项 1–32 个引擎、目标及发布配置齐全。
- 模型参数本步引用已有发布配置，不覆盖温度、超时、凭证或快照。任务级参数覆盖不在此小特性范围。

前后端约定为 `TaskEngineConfiguration` / `iqc-task-processing-v1`，对应后端 PR #66。组件通过 v-model 传出该定义。完整结果处理表单、四步向导父组件和创建/执行接口仍待连接；本 PR 不把该字段直接加入旧创建请求，避免旧后端忽略它而执行错误计划。尚未完成真实浏览器视觉验收。

验证：新增三项组件交互测试，覆盖两个操作、多同类实例、独立排序、切换草稿、发布配置过滤、目标/参数校验、移除及禁用状态；与数据筛选组件测试共七项通过。vue-tsc 和 Vite 构建通过，构建仍有既有的大 chunk 提示。
