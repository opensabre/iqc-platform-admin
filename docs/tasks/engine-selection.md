# 任务类型步骤：独立引擎配置

`TaskEngineSelector` 对应原型第二步“任务类型”，复用现有 Ant Design Vue 表单和规则、大模型配置数据。父级传入已有 API 加载的规则、模型及识别目标，不新增配置查询 API。

- 质检、打标可单选或同时选择，分别添加 REGEX / DLS / LLM；小模型只提示后续支持。
- 同类型允许多个实例；各操作按数组位置独立排序，上移/下移不改变另一操作。切换操作保留本组件生命周期内的草稿。
- 只显示对应类型的已发布规则、已发布且非 RULE_ONLY 的大模型配置。选择规则可查看表达式；请求仅提交引用 ID，不提交表达式或模型快照。
- 目标选项由结果处理配置和既有规则/标签数据提供；组件不创建新标签，不以命中直接写标签。
- `validate()` 在向导下一步或提交前校验：至少选择一项，每项 1–32 个引擎、目标及发布配置齐全。
- 模型引用已有发布配置；每个 LLM 实例独立配置任务提示词、温度和超时，冻结为任务参数覆盖，不修改已发布模型或凭证。

前后端约定为 `TaskEngineConfiguration` / `iqc-task-processing-v1`，组件通过 v-model 传出定义。已连接结果处理表单、四步向导和实际创建/执行链路，不将新计划混入旧请求。真实任务页已验证正则、DLS、LLM 的联合运行与原始结果展示；正式入口登录仍待验收，见 [原型验收记录](prototype-acceptance.md)。

验证：新增三项组件交互测试，覆盖两个操作、多同类实例、独立排序、切换草稿、发布配置过滤、目标/参数校验、移除及禁用状态；与数据筛选组件测试共七项通过。vue-tsc 和 Vite 构建通过，构建仍有既有的大 chunk 提示。

引擎名称：新建时默认生成可读名称，用户可修改为1–80字符。名称随任务冻结，并用于确认页、结果处理映射、任务详情、引擎记录及候选来源；排序/映射仍用实例ID，旧快照无名称时显示ID。后端依赖 task-engine-names 分支。

任务级大模型参数：每个LLM实例分别填写提示词（1–8000字符）、温度（0–1，保留0）及超时（1–120秒）。默认温度0、超时30秒，确认页逐实例显示。参数仅保存在本次任务快照，不修改已发布模型配置；后台对主模型和备用模型一致应用。超时为每次模型请求的传输超时，不是包含多次重试的任务总时长。
