| 需求 | 当前证据 | 仍需补充 |
|---|---|---|
| 四步名称、提交和任务详情衔接 | 实际任务页浏览器创建成功 | 正式应用壳导航 |
| 批量选择 | 本轮实际任务页 | 无新的取数缺口 |

| 模拟列表与不足数量 | 前轮真实浏览器：请求 100、匹配及抽中 1；同列列表 | 大数据量性能不在当前证据范围 |
| 质检和打标独立或联合 | 联合任务本轮通过；单质检前轮通过；后端 #77 验证单打标 HTTP 创建/执行/无评分；结果组件验证单打标默认页签及 false | 单打标完整页面运行 |
| 各操作独立多引擎、排序和冻结配置 | 本轮提交数组、详情和执行记录一致 | DLS/LLM 的页面运行组合 |
| 失败留痕且继续、重试复用成功结果 | 后端 JointLabelMaterializationTransactionTest 联合执行/重试 HTTP 用例 | 浏览器异常组合与历史切换 |
| 原始输入、输出、证据保存 | 后端结果集测试；本轮页面原文证据和配置入口 | 不以截图代替全部持久化断言 |
| 汇总评分、标签且不隐藏冲突 | 本轮同目标双引擎只扣一次、false 保留；组件及处理器测试覆盖冲突 | 冲突完整页面验收 |
| 每个 LLM 的提示词、温度、超时 | 前后端参数及冻结测试；后端 TaskModelHttpParametersTest 通过真实 SDK 向本地端点发出请求，核对主/备用提示词、显式零温度、1 秒超时触发切换及旧默认模型配置不变 | 真实供应商与生产网络不在本地证据范围 |
| 无新增知识库、风险中心、事实语义功能 | 本轮仅任务/结果模块；默认任务结果视图移除风险筛选和列 | 不宣称已删除 main 的历史功能 |

## 2026-11-07 大模型 HTTP 边界补验

后端新增 `TaskModelHttpParametersTest`，复用现有 Provider 和模型路由器，不修改业务实现。
对应 [后端 PR #76](https://github.com/opensabre/iqc-platform/pull/76)，基于后端 PR #75；
本轮 3 项 HTTP 测试及 11 项 Provider/路由回归全部通过，PR 尚未合并或部署。
测试将已发布模型的 30 秒超时、0.8 温度覆盖为任务的 1 秒、0，
通过本地 OpenAI 兼容端点检查实际 JSON 请求；主端点延迟 3 秒时转到备用端点。
同时检查任务提示词与原行为指令均保留、发布快照未修改，及旧默认模型收到相同任务参数。
这些证据补齐上表的客户端 HTTP 参数项，不替代 DLS/LLM 的完整页面组合验收。
