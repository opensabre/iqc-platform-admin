# 结果处理表单

`TaskResultProcessingEditor` 是四步向导的第三步组件，接收第二步的独立引擎计划、
目标名称和通过现有标签详情 API 获取的值定义。父向导组合另行接入。

- 同一质检目标只出现一次评分设置，全部引擎分别设置命中/未命中映射。
- 评分方式、基础分、及格线、项目分值和汇总规则要求明确填写，不套用原型示例。
- 标签选已发布值定义，按类型填写命中/未命中值，或明确勾选未知。
- `false`、`0` 与未知 `null` 分开；缺失 `undefined` 不允许提交。
- 当前汇总规则支持“全部引擎一致时确定”，不一致或缺失仍保留冲突、未知或错误。
- 删除引擎或关闭操作后，旧草稿不进入请求；排序不会丢失映射。
- 变更标签值定义会清空该目标映射，避免旧值误用于新类型。

父组件通过 `validate()` 与 `getConfiguration()` 取得完整配置；校验失败不返回可提交对象。
创建接口类型 `WizardCreateTaskRequest` 对应后端 PR #68，分开传递数据、引擎与结果政策。
此组件不替代后端冻结验证，不执行引擎，也不修改原始结果。
