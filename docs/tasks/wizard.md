# 四步任务创建

任务中心的“创建任务”使用 `TaskCreateWizard`，按原型固定为：

1. 数据筛选：复用 `TaskDataSelector` 和会话表格；批量明确名单，随机/条件保存条件。
2. 任务类型：复用 `TaskEngineSelector`；质检、打标可单选或同时选择，各自排序。
3. 结果处理：复用 `TaskResultProcessingEditor`，独立配置评分、标签和各来源映射。
4. 任务确认：名称、并发、数据范围、各操作执行顺序、结果映射与评分设置。

现有独立质检项属于业务方案的版本定义，没有全局可复用的质检项目录 API。
本向导的质检项是任务内目标：用可读名称作为已有引擎/评分快照的 targetId，
不新增目录或持久化模型；同一名称可被多个引擎引用。标签仍引用现有已发布标签。

提交复用现有任务 API，发送 `dataSelection`、`processingConfiguration`、
`resultProcessing`。即使预览返回种子，也不将预览种子提交为正式取数参数。
创建成功进入实际任务详情，列表手动执行；旧任务继续使用已有查看和执行逻辑。
动态模式运行前显示“执行时确定”，不把尚未解析的名单当作零个会话。

标签值定义加载失败可重试，阻止不完整提交；参数错误保留表单。
网络无法确认创建是否成功时保留草稿并阻止再次提交，提示先核对列表。
当前接口没有新请求标识协议，尚不支持自动恢复未知状态的提交。

原始结果/评分/标签展示以及真实后端全流程验收；本页面的本地浏览器检查
使用拦截的 API 数据，不代表线上或完整后端验收。
